# Технический аудит Match Studio — 31.07.2026

## Область проверки

Проверены изменения PR №15 в ветке `feature/manual-build-dynamic-vars`: CRUD YAML-файлов, `global_vars`, конвертация триггеров в RegExp, рабочая копия и сохранение, диагностика, Windows portable workflow.

## Выявленные риски

### Критические

1. **Удаление YAML не было транзакционным.** Сначала сохранялось удаление из `imports`, затем выполнялся `remove_file`. При ошибке удаления конфигурация уже менялась, а файл оставался на месте.
2. **Откат включения/выключения YAML восстанавливал имя файла, но не рабочую копию `base.yml`.** После ошибки в памяти мог оставаться несохранённый вариант `imports`.
3. **Повторное переключение Trigger → RegExp могло использовать устаревшее скрытое выражение.** RegExp обновлялся только при пустом поле.

### Высокие

1. Файловая логика, Windows-валидация имён и UI находились в одном `app.rs`, что затрудняло независимое тестирование.
2. На каждое изменение структурированного правила выполнялся полный сбор `global_vars` по проекту, даже когда пользователь менял название или печатал обычный текст.
3. Windows-имена вида `CON.backup.yml` и основы с завершающим пробелом блокировались не полностью.

### Средние и остаточные

1. `app.rs` всё ещё остаётся крупным оркестратором. Следующий этап — вынести сервис глобальных переменных и диалоги CRUD в отдельные контроллеры.
2. Инвентаризация `global_vars` прекращается при ошибке разбора одного файла. В дальнейшем стоит показывать корректные переменные из остальных файлов вместе с локальной ошибкой.
3. Диагностика и файловый монитор выполняются в UI-потоке. Для очень больших наборов YAML нужен фоновый снимок с передачей результата в интерфейс.
4. Необходим ручной smoke-test на Windows для блокировки файла антивирусом или редактором в момент удаления и переименования.

## Выполняемый рефакторинг

- Файловые пути, `.disabled`, безопасный карантин и Windows-валидация вынесены в `yaml_files.rs`.
- Преобразование обычных триггеров в RegExp вынесено в `trigger_conversion.rs` и сделано детерминированным.
- Удаление выполняется через переименование в карантин, сохранение `imports`, затем окончательное удаление. При ошибке файл и рабочая копия восстанавливаются.
- Включение и выключение YAML восстанавливает не только имя файла, но и снимок рабочей области.
- Автодобавление встроенных переменных запускается только при появлении нового завершённого `{{placeholder}}`, а не на каждый символ.
- Добавлены модульные тесты для суффиксов, карантина, Windows-имён, RegExp-конвертации и определения новых встроенных переменных.
