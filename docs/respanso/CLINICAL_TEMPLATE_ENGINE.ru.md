# Clinical Template Engine

## Цель

Clinical Template Engine отделяет медицинское содержание от кода rEspanso. Осмотр, именованные поля, вычисления, правила и ссылки на источники описываются JSON-пакетом версии `schema_version: 1`. Обновление приказа или клинической рекомендации не требует пересборки приложения: меняется пакет, затем он валидируется и только после этого сохраняется как активный.

Старый Clinical Extender не заменяется и продолжает работать независимо. Новый движок расположен в отдельной вкладке **Template Engine**.

## Модель данных

Пакет содержит:

- `fields` — именованные поля: `patient.age`, `vitals.weight_kg`, `labs.creatinine_umol_l`, `renal.egfr`;
- `calculations` — встроенные калькуляторы, Rhai-формулы или sandboxed Rhai-скрипты, каждый с явными входами и одним выходом;
- `rules` — структурированный AST условий и действий;
- `sections` — текстовые секции осмотра с подстановками `{{field.id}}`;
- `source` — необязательная трассировка к приказу/КР/разделу документа.

Контекст пациента можно передавать вложенным JSON:

```json
{
  "patient": {"age": 67, "sex": "male"},
  "vitals": {"height_cm": 176, "weight_kg": 92},
  "labs": {"creatinine_umol_l": 185}
}
```

Движок автоматически преобразует его во внутренние пути `patient.age`, `vitals.height_cm` и т. д.

## Вычисления

Поддержаны три режима:

1. `builtin` — встроенный проверяемый калькулятор. В первой версии есть `bmi` и `ckd_epi_2021`.
2. `formula` — Rhai-выражение, работающее только с объявленными входами.
3. `script` — Rhai-фрагмент, возвращающий одно вычисляемое значение.

Rhai runtime не регистрирует файловые, сетевые или shell-функции и имеет лимит операций. Скрипт не получает прямой доступ к ОС.

Зависимости вычисляются до фиксированной точки: изменение исходного поля может разблокировать вычисляемое поле, которое затем активирует правило и последующие изменения.

## Условия

Условия хранятся структурированно, а не строкой:

```json
{
  "op": "lt",
  "left": {"var": "renal.egfr"},
  "right": {"value": 60}
}
```

Поддерживаются `all`, `any`, `not`, `exists`, `eq`, `ne`, `lt`, `lte`, `gt`, `gte`.

## Действия правил

Первая версия поддерживает:

- `set` — установить поле;
- `require` — сделать поле обязательным;
- `show` / `hide` — управлять видимостью;
- `warning` — диагностическое сообщение;
- `recommendation` — рекомендация;
- `append_text` — добавить текст в секцию;
- `activate_module` — попросить внешний слой подключить другой модуль.

## Validation gate

Пакет нельзя сохранить через Studio, пока не пройдены:

- проверка версии схемы;
- уникальность id полей, вычислений и правил;
- наличие всех зависимостей;
- существование полей, к которым обращаются правила;
- наличие секций для `append_text`;
- ограничение размера Rhai-скриптов.

Это позволяет агенту сгенерировать JSON, но не даёт ему бесконтрольно менять активную клиническую логику.

## Агентный workflow

Предполагаемый процесс:

1. Пользователь передаёт приказ/КР агенту.
2. Агент извлекает поля, вычисления, зависимости, правила и источники.
3. Агент генерирует draft JSON package.
4. Package открывается во вкладке Template Engine.
5. Выполняется validation и тестовый evaluate на синтетическом контексте.
6. Пользователь проверяет diff/источники.
7. Только затем JSON сохраняется как `clinical_extender/template-engine.json`.

В следующих итерациях поверх этого контракта можно добавить MCP-команду `clinical_template.validate/evaluate/import` без изменения формата пакета.

## Windows

Для локальной Windows-проверки добавлен `scripts/build_windows_engine_template.ps1`. Он выполняет check/test/release build и собирает существующий portable archive. GitHub Actions автоматически не запускаются для ветки `feat/engine-template`.

Пример JSON лежит в `espanso-editor/examples/clinical-template-package.example.json`.
