# Промпты для генерации Rhai-скриптов rEspanso

Ниже приведены готовые промпты, учитывающие фактический контракт встроенного runtime и реактивного предпросмотра.

## 1. Один Rhai-скрипт

```text
Ты пишешь Rhai-скрипт для rEspanso.

Обязательный контракт runtime:
- файл должен содержать функцию fn calculate(input) { ... };
- rEspanso вызывает функцию calculate и передаёт ей один аргумент input;
- последнее выражение верхнего уровня файла НЕ является результатом;
- input может быть строкой или map, это будет явно указано в задаче;
- поля формы всегда приходят строками;
- разрешены базовые возможности Rhai: строки, числа, массивы, map, функции и if;
- round(value) и value.round() доступны;
- eval и import отключены;
- shell, сеть, файловая система и внешние процессы недоступны;
- не выдумывай функций, которых нет в стандартном Rhai или в описанном runtime.

Требования к качеству:
1. Сделай код детерминированным и читаемым.
2. Явно проверь пустые, некорректные и граничные значения.
3. Для десятичных чисел из русской формы поддержи запятую через replace(",", ".").
4. Оборачивай parse_int/parse_float в try/catch и возвращай status: "error" вместо аварийного завершения preview.
5. Не используй бесконечные циклы, eval, import и отладочную печать.
6. Для простого преобразования верни строку.
7. Для калькулятора верни map:
   #{
       status: "ok",
       value: <основное значение>,
       text: <полный человекочитаемый результат>
   }
8. При ошибке валидации верни:
   #{
       status: "error",
       value: "",
       text: <понятное сообщение пользователю>
   }
9. Не меняй медицинскую, юридическую или финансовую формулу без явного источника и указания версии.

Формат ответа:
1. Имя файла в scripts/.
2. Полный код Rhai одним блоком.
3. Ожидаемый тип input и список полей.
4. Минимальный YAML подключения.
5. Не менее трёх тестов: обычный, граничный, ошибочный.
6. Краткие ограничения.

Задача:
<опишите требуемое вычисление или преобразование>
```

## 2. Реактивная форма + Rhai

```text
Создай полный рабочий комплект для rEspanso: YAML-правило с реактивной формой и отдельный Rhai-скрипт.

Контракт реактивного предпросмотра:
- форма задаётся как type: form;
- в params должны быть preview: true, preview_mode, preview_layout, layout, fields и computed;
- computed-узел имеет type: rhai, path, function: calculate и depends_on;
- Rhai получает map input со всеми текущими полями формы;
- все поля формы являются строками;
- preview_layout обращается к map результата как {{result.text}} и {{result.value}};
- после подтверждения формы поля computed доступны как:
  {{form_var.result}}
  {{form_var.result__value}}
  {{form_var.result__text}}
- итоговый replace должен использовать computed-результат напрямую;
- НЕ создавай второй type: rhai после формы и не выполняй расчёт повторно;
- depends_on задаёт порядок между computed-узлами, а не фильтрацию изменений обычных полей;
- для одного узла укажи depends_on: [].

Требования к Rhai:
- обязательно fn calculate(input) { ... };
- успешный калькулятор возвращает #{ status: "ok", value: ..., text: ... };
- ошибка возвращает #{ status: "error", value: "", text: ... };
- значения с десятичной запятой нормализуются перед parse_float;
- parse_int/parse_float обёрнуты в try/catch с возвратом status: "error";
- не используй eval, import, shell, сеть, файлы и внешние процессы;
- не выдумывай неподдерживаемый синтаксис.

Требования к YAML:
- начни с matches:;
- используй путь %CONFIG%/scripts/<имя>.rhai;
- все шаблоны {{...}} и поля [[...]] должны быть согласованы;
- итоговый replace должен ссылаться на {{form_var.result__text}} или другое реально возвращаемое поле;
- выдай YAML целиком, без пропусков и псевдокода.

Формат ответа:
1. Полный Rhai-файл.
2. Полный YAML-файл.
3. Таблица соответствия field -> input.<field>.
4. Тестовые наборы и ожидаемый preview.
5. Ограничения и проверяемые источники формулы.

Задача:
<опишите форму, поля, формулу и желаемый текст результата>
```

## 3. Аудит существующего комплекта

```text
Проверь и исправь приложенные YAML и Rhai для rEspanso.

Проверяй строго:
1. В Rhai есть fn calculate(input), и именно её вызывает YAML.
2. path указывает внутрь %CONFIG% или %PACKAGES%.
3. Все имена fields совпадают с input.<field>.
4. Все значения формы трактуются как строки и разбираются явно.
5. Каждый parse_int/parse_float защищён try/catch и возвращает status: "error" при неверном вводе.
6. preview_layout использует {{node.field}}, а итоговый replace — {{form_var.node__field}}.
7. type: form не подставляется как {{form_var}} без подполя.
8. Нет повторного Rhai-расчёта после формы, если уже используется computed.
9. Ошибки валидации возвращают status: "error" и понятный text.
10. Успех возвращает status: "ok", value и text.
11. depends_on не содержит ложных предположений о частичном пересчёте полей.
12. YAML полностью валиден, отступы и кавычки корректны.
13. Не изменяй формулу или клинические пороги без отдельного объяснения.

Верни:
- перечень найденных ошибок;
- полностью исправленный Rhai;
- полностью исправленный YAML;
- тесты для preview и submit;
- краткое описание изменённого контракта.
```

Медицинские, юридические и финансовые расчёты перед публикацией должны проходить отдельную проверку формул, источников, единиц измерения и граничных условий.
