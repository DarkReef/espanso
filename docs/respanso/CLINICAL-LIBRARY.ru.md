# Раздельная библиотека нозологий

В папке конфигурации `clinical_extender/base.yml` хранится общий профиль,
каталог общих обследований и общие определения полей. В
`clinical_extender/nosologies/` каждая нозология хранится отдельным YAML-файлом.
Имена файлов редактор формирует из кода; спецсимволы масок кодируются.

Базовый профиль применяется всегда. Обследования выбранных нозологий добавляются
к базовым и объединяются по `id` без повторов. Текстовые разделы дополняют базу,
сохраняя прежний порядок композиции. Галочки унаследованных обследований
помечены «из базы»; изменять их нужно в базовом профиле.

У нозологии есть собственные `catalog`, `investigation_ids`, `fields` и `sections`.
Кнопка добавления обследования сохраняет его определение в текущей нозологии.
В редакторе шаблона можно добавить поле и задать его тип/варианты. Для вставки
значения в текст используйте `{{field_name}}`. Определённые поля отображаются
при выборе нозологии, даже если пока не вставлены в её текст.

Определение поля с тем же именем переопределяет базовое только для выбранной
нозологии. При нескольких выбранных шаблонах применяется прежний порядок:
база, маски, точные совпадения, псевдонимы; позднее определение побеждает.
При равной специфичности учитывается порядок диагнозов. Для независимых
по смыслу полей используйте разные имена. `today` и `visit_date` — системные.
Значения полей пациента не сохраняются в файлы библиотеки.

Старый `nosologies.yml` читается, пока отсутствует `base.yml`. При первом
сохранении создаются отдельные файлы; старый файл остаётся без изменений.
После перехода используется только новый формат. Исправления базы автоматически
учитываются во всех нозологиях при следующем открытии библиотеки.

Сохранение сначала готовит и проверяет полный набор в соседней временной папке,
затем заменяет рабочую папку. Предыдущее состояние остаётся в
`clinical_extender.previous`. Это резервная копия последнего сохранения,
не полная история версий. Если процесс оборвался между переименованиями,
при загрузке восстанавливается предыдущая папка. При повреждённом YAML
сохранение блокируется: исправьте файл и перезапустите редактор.

Внешние изменения YAML делайте при закрытом редакторе. В новую папку можно
добавить собственный `.yml` или `.yaml`; после сохранения редактор приведёт
имя к своему формату. Не создавайте два файла с одинаковым кодом нозологии.
Список `order` в базовом файле сохраняет порядок шаблонов; новые файлы,
которых в нём нет, также загружаются.
