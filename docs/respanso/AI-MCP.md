# ИИ и MCP в pol_run

## Быстрый старт: Astra Linux / KDE / X11

1. Соберите полный portable-пакет через workflow `pol_run Astra 1.7 X11 full portable` на ветке с изменениями. Сборка использует Debian 10 / glibc 2.28; на рабочем месте sudo не нужен.
2. Запустите `run.sh`. В Studio откройте **ИИ / MCP**.
3. Включите ИИ, выберите OpenAI или GigaChat, введите ключ и модель. Сохраните настройки. Для отдельного окна Alt+L сохраните ключ на устройстве либо задайте переменную окружения перед запуском движка. Ключ, введённый без сохранения, действует только в текущем окне.
4. Запишите свой контекст, например: «Я врач-терапевт. Оформи краткую запись в связный медицинский текст. Сохрани указанные факты, сроки, числа и отрицания».
5. В МИС выделите короткую запись, отпустите клавиши после **Alt+L**. Откроется отдельное окно ИИ; обычные подстановки продолжают работать.
6. Проверьте текст и контекст после локальной маскировки. Удалите пропущенные идентификаторы, отметьте проверку и нажмите **Переформулировать**.
7. Прочитайте и при необходимости исправьте результат. **Вставить в исходное окно** вернёт фокус и отправит Ctrl+V. Вставка заменяет выделение, которое сейчас существует в этом окне: не меняйте его во время обработки. Если окно закрыто или фокус не удалось вернуть, используйте **Копировать результат** и ручную вставку.

Кнопка возврата в исходное окно доступна на Linux/X11 при наличии xdotool. В portable-сборку включены xdotool и libxdo; глобальный Alt+L регистрируется самим движком, отдельный демон клавиш не нужен. При конфликте Alt+L с KDE/другой программой освободите сочетание в настройках этой программы. Вкладка ИИ работает и без горячей клавиши.

Пример исходника: «Боль пять дней в животе, тяжесть в эпигастрии, дыхание с хрипами».
Ожидаемый смысл результата: «Боль в животе в течение пяти дней, тяжесть в эпигастральной области. Отмечается дыхание с хрипами».
Нельзя дописывать «обратился сегодня», локализацию всех болей в эпигастрии, влажность хрипов, диагноз или назначения, если этого нет в исходнике. Формулировку про хрипы врач уточняет по источнику: жалоба это или результат аускультации. Системная инструкция ограничивает дополнения, но проверку врача не заменяет.

## API и данные

- OpenAI: отдельный API-ключ `OPENAI_API_KEY`, Responses API, `store: false`. Это вызов модели через API, не управление текущим чатом или подпиской ChatGPT. Модель настраивается; исходное значение — `gpt-4.1-mini`.
- GigaChat: ключ авторизации Base64 в `GIGACHAT_AUTH_KEY`, без `Basic`; приложение само получает Bearer-токен через OAuth. Scope: `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Модель настраивается, по умолчанию `GigaChat`.
- Используется актуальный адрес `https://api.giga.chat/v1/chat/completions`; OAuth — `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`. Краткоживущий токен остаётся в памяти одного запроса, не записывается на диск. Повторная обработка получает новый токен.
- TLS проверяется всегда. При необходимости укажите доверенный корневой сертификат PEM. Отключения проверки сертификатов нет.
- Отправляются только проверяемый текст и настроенный контекст с фиксированными правилами; файлы МИС, соседние окна, история буфера и YAML-правила автоматически не читаются.
- Маскировка типовых ФИО, контактов, дат, СНИЛС и номеров полиса — эвристика, не гарантия обезличивания. Она применяется и к контексту. Системная инструкция «игнорировать ПДн» не предотвращает их передачу. Перед отправкой требуется проверка.
- Текст и ответы не записываются в журналы или историю приложения. После копирования результат остаётся в системном буфере; внешние менеджеры буфера могут вести свою историю.
- Настройки находятся в `ai.json`, ключи отдельно в `.ai-OPENAI_API_KEY.key` / `.ai-GIGACHAT_AUTH_KEY.key`. Файлы на Linux создаются атомарно с правами 0600, но не шифруются. Не отправляйте рабочую папку целиком. Штатный экспорт match/scripts не включает эти файлы. Переменные окружения имеют приоритет при загрузке ключей.
- Лимит входа 24 КБ UTF-8, ответа API 1 МиБ, сетевой таймаут 60 секунд на запрос. При ошибке или неполном ответе автоматической вставки нет. Закрытие окна прекращает его процесс; уже отправленный запрос на стороне провайдера отозвать нельзя.

## Что делает MCP

Обработка по Alt+L вызывает API провайдера напрямую. MCP — отдельный стандартный интерфейс, через который локальный ИИ-клиент вызывает инструменты rEspanso. Сервер реализует JSON-RPC 2.0, MCP `2025-06-18`, stdio, initialize/initialized, ping, tools/list, tools/call.

Инструменты:

| Инструмент | Действие | Сеть |
|---|---|---|
| `get_context` | Показать маскированный контекст, правила и выбранного провайдера без ключей | Нет |
| `prepare_text` | Локально замаскировать типовые идентификаторы | Нет |
| `rewrite_text` | Переформулировать проверенный текст через выбранный API | Да, только при включённых ИИ и разрешении MCP в локальных настройках |

Клиент должен показать пользователю контекст и подготовленный текст перед вызовом `rewrite_text` с `reviewed: true`. Это заявка клиента о проверке, а не доказательство согласия; подключайте сервер только к доверенному локальному клиенту с подтверждением сетевых вызовов. MCP не читает буфер, не вставляет текст, не запускает shell-команды и не отдаёт ключи.

В локальном MCP-клиенте с поддержкой stdio задайте, например:

```json
{
  "mcpServers": {
    "respanso": {
      "command": "/home/user/rEspanso/mcp.sh"
    }
  }
}
```

При запуске сборки напрямую:

```json
{
  "mcpServers": {
    "respanso": {
      "command": "/absolute/path/espanso-editor",
      "args": ["--mcp", "--config-dir", "/absolute/path/espanso-config"]
    }
  }
}
```

`--mcp` не открывает GUI и не требует DISPLAY. Сервер не слушает TCP-порт. Веб-чат ChatGPT и GigaChat не подключаются к локальному stdio-процессу по одному API-ключу: для этого нужен совместимый клиент/агент на компьютере. Публичный HTTP-шлюз для ChatGPT в эту реализацию не входит.

## Проверка

Команды разработчика:

```sh
cargo test -p espanso-ai -p espanso-engine -p espanso-config -p espanso-match -p espanso-render -p espanso-editor
cargo build -p espanso --bin espanso --no-default-features --features modulo,vendored-tls
cargo build -p espanso-editor
bash -n scripts/build_pol_run_astra17.sh
```

Сборка в Debian 10 проверяет ABI, но не удостоверяет поведение всех МИС или политик Astra. На целевом рабочем месте проверить: запуск без sudo, трей, кириллицу, формы, поиск, Rhai, CRUD/импорт YAML, Alt+L в русской и английской раскладках, одинаковое повторное выделение, пустое выделение, возврат фокуса, отключённый ИИ, неверный ключ, сетевой отказ, OpenAI/GigaChat с синтетическим текстом. Реальные клинические данные для проверки не нужны.

Официальные протоколы: [MCP lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle), [MCP tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools), [OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create/), [GigaChat авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).
